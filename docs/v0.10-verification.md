# v0.10 verification record (2026-11-09)

Two Extras plugins on the existing Depth Anything V2 tool, own implementation with ImageIO (no upstream code, no new dependency):

| Plugin id | Issue | What it does | Not covered |
| --- | --- | --- | --- |
| `depth_image_io` | #37 | Import: your own 8/16-bit depth PNG, stretched to full range, optional invert, resized to the input, returned as 8-bit depth. Export: 16-bit grayscale PNG of the estimated depth (never overwrites) | depth2img model wiring of the original extension (the app has no depth2img-specific path); `.npy`/EXR files; the export is a 16-bit container of the 8-bit estimate, not extra precision |
| `depth_library` | #38 | Folder of named depth maps: Save (estimate + store, no overwrite), Load (resized to the input), List | The original's bundled depth collection (none bundled), a thumbnail browser UI |

Checks: `DepthIoSuite` (16-bit read/write, normalize/invert/resize, import/load/list, name and overwrite rules) and the full plugins suite.
Real GUI check (`RealDepthIoCheck`, real `MainWindow` img2img tab, scala-torch, RTX 3090, SD1.5 `animekawa_v10` loaded, 512x512 source from
an earlier generation): Save created `meadow.png` (preview dynamic range 0..252); Load returned an identical 8-bit map (max diff 0); Export wrote a
16-bit PNG (PIL mode I;16, 512x512); Import of that file gave a 512x512 map and Invert was its exact complement. Images viewed: the
depth map separates the girl from the hills and sky, and the inverted import flips it. The depth model does not depend on the checkpoint,
so SDXL was not re-run.
