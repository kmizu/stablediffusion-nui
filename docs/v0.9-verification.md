# v0.9 verification record (2026-11-09)

`infinity_grid` (#65): Script plugin, own YAML format and implementation (no upstream code). A YAML with `axes:` (steps, cfg, sampler,
seed, width, height, prompt, negative; values separated by `,` or `|`) generates every combination with one fixed seed. Axis 1 = columns,
axis 2 = rows, every further axis creates one more grid page; the grids are returned/saved as grids and the single images stay available.
A safety limit (default 64 images) rejects oversized grids before any generation.

Checks: `InfinityGridSuite` (parsing and rejects, combination maths, prompt appending, one seed, page count, limit) and the full plugins
suite. Real GUI check (`RealInfinityGridCheck`, real `MainWindow` txt2img tab, scala-torch, RTX 3090): SD1.5 `animekawa_v10` 2x2 grid
(prompt red/blue hair x steps 6/14) gave 4 cell images with the expected prompts, steps and one seed, plus a labelled 1134x1074 grid
(viewed: columns labelled by prompt, rows by steps; 6 steps visibly rougher than 14); SDXL `waiIllustriousSDXL_v170` 4 cells generated.

Not covered: the original's description fields, web page output, multi-value `Sampler`/`model`/LoRA axes beyond the listed names,
resuming an interrupted grid, SDXL grid image inspection (only the SDXL cell count was checked).
