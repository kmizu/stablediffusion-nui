## Behaviour

- **Clip Output** (while generating): the CLIP conditioning of the Positive prompt (and, if a name is given, the Negative prompt) is written once per request to the conditioning folder, `$SDFX_CLIP_IO_DIR` or `~/.cache/stablediffusion-nui/clip_io/conditioning`. `.csv` or `.pt` by the name's extension (default from the Format control). One row per token, one column per dimension; Transpose matrix swaps them; Add token strings adds the token text as first column (first row when transposed; numeric-looking strings get a `'` prefix so a reader cannot mistake them for numbers). Options: no bos/eos/pad tokens (the chunk's real tokens only), Ignore emphasis (weights 1; emphasis syntax is still parsed), Bypass conditioning normalization (no mean rescale after weighting), Overwrite (otherwise an existing file is kept and a warning is given). The first step of a prompt schedule is exported. With default options the exported matrix is exactly what generation encodes. Names cannot leave the folder (absolute paths, `..`, drives refused).
- **.pt format**: a tensor (tokens x dim); SDXL files are a dict `{cond, pooled, tokens}`. Loaded with `weights_only=True` (a pickled payload is refused).
- **Clip Input**: the Positive / Negative prompt boxes (modes Off / Simple / Directive) become lists of conditioning files. Names are space separated, quoted when they hold spaces, tried as given, then `.csv`, then `.pt`; `"""text"""` is encoded by CLIP; all pieces are concatenated along the token axis. Directive mode adds `?prompt("""text""", clip_skip=2, no_padding=False)` (positional arguments may be omitted, prompt / clip_skip / no_padding may be lists, the last clip_skip is broadcast) and `?eval(expr)` / `?eval_ORDER(expr)` (ascending order, ties left to right; run after the pieces are joined; `i` and `o` are the conditioning before the directive, `t` and `d` the token and dimension index). `eval` is a restricted, vectorised arithmetic interpreter (no Python eval). Width must fit the model (768 / 1024 / 2048). Positive and negative are made equal in length by appending the empty prompt's rows (zeros for an all-zero SDXL negative).
- Only the generation's own prompts are replaced; ADetailer or Hires override prompts are encoded normally. SDXL pooled vectors: from the `.pt` file, else the empty prompt's (a CSV carries none, so an SDXL CSV input is not identical to the original).
- Settings are written to the infotext (`Clip Input positive|negative`, `Clip Output`, `Clip Output negative|format|options`) and restored from PNG, the MCP inspect tool and the UI. A replay needs the same conditioning files.
- Dry-run engine: validates the settings and the file names (no encoding).

## Not provided

`?exec`, the `g` (carry-over dict) and `p` (processing object) names of `eval`, arbitrary Python in `eval`; prompt editing, alternating words, AND and BREAK inside input prompts; an in-app file browser for the conditioning folder (use the folder); embedding editing beyond arithmetic.

## Verification run

- Python: `python/tests/test_clip_io.py` (syntax, directives, restricted eval including injection attempts, CSV/PT round trips in every layout, pickle refusal, encoding options on a tiny fake CLIP, export/input round trip, SDXL pooled, engine wiring); full CPU suite 2859 passed, 2 skipped. Scala: `ClipIoSuite` and the MCP inspect test; full `sbt test` passed except one `ScriptsSuite` 30 s timeout under load, which passed when run alone; `ui/assembly` built.
- Real runs through the official MCP SDK with the built jar (`scripts/dev/check_clip_io_real.py`, receipts in `outputs/clip-io-real-{sd15,sdxl}`): SD1.5 `animekawa_v10` 512x512 and SDXL `waiIllustriousSDXL_v170` 832x1216 (`sequential_offload`), 20 steps, Euler. Earlier attempts failed on mistakes in the check itself (a too strict rounding assertion, the negative prompt using another clip skip, SDXL clip skip 1 equal to 2 and its "!" pad token) and were fixed in the script, not the code.
  - Exporting leaves the image byte-identical. CSV with token strings: 77 rows, 769 (SD1.5) / 2049 (SDXL) columns, first `<|startoftext|>`, last `<|endoftext|>` (SD1.5) / `!` (SDXL's second tokenizer). No special tokens: 5 rows `a lion , a tiger`. Transposed: 769 / 2049 rows by 5 columns, equal to the untransposed values. Ignore emphasis equals the unweighted prompt exactly; normalisation is one global factor (0.941-0.942 on SD1.5).
  - Feeding the exported `.pt` (positive, or both sides) reproduces the baseline byte-for-byte, also with batch 2 and with Hires fix. CSV input is exact on SD1.5 and differs on SDXL, as documented. A clip-skip-2 (3 on SDXL) export fed back equals the request at that clip skip. `?eval(i)` and `?eval_2(i*2) ?eval_1(i/2)` are exact; `?eval_1(i+0.5) ?eval_2(i*2)` equals the swapped textual order and differs from the other order. `?prompt('''text''')` equals ordinary encoding and a clip-skip `?prompt` equals the matching export.
  - Changes: combined prompt (file plus a CLIP piece) mean abs diff 0.061 / 0.192, `i*0.7` 0.125 / 0.173, sine wave 0.053 / 0.036, no-padding prompt 0.149 / 0.240, mixed clip skips 0.146 / 0.235 (SD1.5 / SDXL).
  - PNG replay reproduces the image; the inspect tool returns a typed candidate with no unapplied Clip fields. Seven invalid inputs fail with clear messages and the next plain run equals the baseline.
- Images viewed (contact sheets baseline, input, combined, eval scale, eval wave, no padding, mixed skips, hires): SD1.5 baseline and file input are identical; combined shows the lion and tiger forest with a different composition; scale and wave give softer / drifted paintings. SDXL baseline and input are identical; combined adds the requested castle on a hill; scale turns the lion into a sketch-like drawing; wave stays close to the baseline. The no-padding prompt (an almost bare conditioning) gives unrelated images (SD1.5 a tiger collage, SDXL an explicit anime figure, deleted from the outputs; it is the checkpoint's behaviour for near-empty conditioning).

Not verified: the JavaFX form was not driven by hand (controls and replay are unit-tested), SD2 / inpaint models, cancel recovery (the hook holds no state besides files).
