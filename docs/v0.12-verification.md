# v0.12 verification record (2026-11-10)

## width / height limit removed

Before: `width must be a multiple of 8 in 64..4096` (client, MCP schema, presets, UI spinner, job limits).
Now any width and height from 1 to 65536 is accepted everywhere (GUI spinner, MCP `txt2img`/`img2img`, presets, history drafts, job limits).
The engine works on whole latents, so the generated size is **rounded up to a multiple of 8 (at least 64)**; the infotext `Size:` records the
size that was generated (`GenerationParams.withEngineSize`, applied once in `Generator.prepare`). The GUI sliders still run 64..2048 for
convenience, the number field accepts any value. 65536 only guards against integer overflow. What still limits a request is memory: the MCP
job limits keep a pixel cap per generation (16.7 Mpx) and the native engine reports `attention score workspace limit exceeded` when the
attention of a very large latent cannot fit (below).

Real check on the extracted package ZIP (clean environment, MCP, scala-torch, cuda:0, saved settings with dtype fp16 / vram_mode auto):

| Request | Generated | Result |
| --- | --- | --- |
| SD1.5 513 x 777 | 520 x 784 | image viewed |
| SD1.5 40 x 30 | 64 x 64 | image viewed (tiny, as expected) |
| SDXL 1366 x 770 | 1368 x 776 | image viewed |
| SDXL 600 x 1500 | 600 x 1504 | image viewed |
| SD1.5 4201 x 256 (above the old 4096) | not generated | accepted by validation and limits, then the native engine stops with `attention score workspace limit exceeded` (default budget 2^30 score elements); a memory limit, not a size rule |

## SDXL "native parameter loading requires fp32 and cpu"

The native worker rejects `load_model` unless `dtype=fp32` and `vram_mode=cpu`. The app forced these values only once at startup, so after the
backend was switched at run time, or when the saved python-era `dtype` / `vram_mode` reached the request (generation path: `Generator.ensureModel`),
the worker answered with that error. `EngineBackend.loadModes` now decides per request: on the native backend always fp32 / cpu, otherwise the
saved values. Verified with the package above whose settings.json holds dtype fp16 / vram_mode auto and SDXL: loads and generates.

Checks: `GenerationParamsSuite` (any size valid, rounding, bounds), `EngineBackendSelectionSuite` (load modes), `GeneratorSuite`, `McpToolsSuite`,
`GenerationVMSuite`, `NativePresetsCoverageSuite`, python `test_params.py` / `test_server_dryrun.py`; engine, mcp and ui suites pass.
