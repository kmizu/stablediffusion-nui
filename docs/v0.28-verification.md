# v0.28 verification record (2026-11-12)

Goal: one switch for the speed-ups that change the image a little, decided by the owner ("keep them optional and add a fast preset").
scala-torch `0.1.3-gh49`. All numbers: RTX 3090, MCP, fp16, 20 steps, Euler a, second generation in the same process, on the extracted
v0.28 ZIP (path with a space), cuDNN from a PyTorch installation.

## Change

New built-in plugin **Fast mode** (`fast_mode`, off by default). Switched on, it adds two things to a request unless the request
already has them:

- DeepCache: a full U-Net step every 3 steps, 5 full steps first (Ma et al., CVPR 2024);
- CFG for the first 70 % of the steps only: the CFG steps from the request's value to 1, and at 1 the engine does not compute the
  negative prompt (after Kynkäänniemi et al., "Applying Guidance in a Limited Interval", 2024).

Two controls: "CFG until" (0.3 to 1, 1 = all steps) and the DeepCache interval (0 = no DeepCache). The DeepCache and CFG Schedule
plugins keep their own values when they are switched on. Both parts need the scala-torch engine features `deepcache` and
`cfg_schedule`.

scala-torch gh49 against gh48 (v0.27): measurement tools and three options that are off by default (packed attention projections,
cross-attention context cache, cuDNN algorithm by measurement); none of them changed a generation time when switched on.

## Measured

Same package, plain against Fast mode, two rounds:

| Request | plain | Fast mode |
| --- | --- | --- |
| SD1.5 512, 1 image | 1.5 / 1.5 s | 1.2 / 1.2 s |
| SD1.5 512, batch size 4 | 4.3 / 4.3 s | 3.3 / 3.4 s |
| SD1.5 512, batch size 8 | 7.7 / 7.7 s | 5.9 / 6.0 s |
| SDXL 1024, 1 image | 7.3 / 8.0 s | 4.3 / 4.5 s |
| SDXL 1024, batch size 2 | 13.9 / 14.5 s | 8.0 / 8.2 s |

No request failed; the file counts were right. The saved PNG carries `Fast mode: "CFG until 0.7, DeepCache interval 3"`.

For comparison, reForge itself on this PC earlier the same day (see the v0.27 record; not the same minutes): 1.4 s, 4.3 to 4.4 s, 7.6 to
8.3 s, 7.1 to 7.3 s and 14.0 to 14.1 s. With default settings SDNUI is close to reForge or slower (between sessions SDNUI's own times
moved by 5 to 10 %); with Fast mode it is faster than reForge's default in every row, at the price of a changed image.

sweater are fainter and the eye colour differs (yellow against grey; the prompt names no eye colour). It is a draft mode: switch it off
for a final render.

## Not covered

- The plugin was driven through MCP (`always_on: {"fast_mode": {"enabled": true}}`); its panel was not operated in the GUI.
- Restoring Fast mode from a PNG's infotext is not implemented (the key is written, not read back).
- Fast mode was run with Euler a and the default values only. With LoRA, ControlNet or hires fix the request leaves the batched path;
  DeepCache refuses ControlNet.
- The Python engine was not tried with this plugin.
- No GPU with less than 24 GB.
