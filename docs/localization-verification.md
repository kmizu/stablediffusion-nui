- **No upstream pack is bundled or redistributed.** The unlicensed ones (9 of 17 repositories) are never copied into this
  repository or the installer. The app downloads a pack only when the user presses *Download* in Settings > Language,
  from the pinned commit on `raw.githubusercontent.com`, checks the byte size and SHA-256 recorded in `store.json`
  (a mismatch saves nothing), and writes it to `<app>/localizations/` next to `<name>.source.txt` (origin, commit, hash,
  licence) and, when the repository has one, `<name>.LICENSE.txt` (hash checked as well). This is the same thing
  `git clone` into `extensions/` does for an A1111 user; for the unlicensed repositories the note says "downloaded for
  your own use, not redistributed".
- The L4Ph ja_JP repository is CC0-1.0. It was still not bundled: its keys are A1111's wording (10 % of this window's
  texts match), so the built-in Japanese pack is a separate native one written for this app's labels.
- The built-in `ja_JP` pack (`core/src/main/resources/sdfx/localizations/ja_JP.json`) was written for this application by
  the author of this change from the application's own strings (collected from the running window, see below); no
  upstream text was copied.
- `scripts/third_party.py` gained 19 entries (17 `data (downloaded on request)` with the pinned commit, hash-pinned
  licence text for the 10 licensed ones, `PINNED_UNLICENSED` for the 9 others; 2 `reimplemented` for the Bilingual
  extensions); `THIRD_PARTY_NOTICES.md` and `licenses/*` were regenerated.

## What the extensions do and what this change provides

| Extension behaviour | This app |
|---|---|
| Language pack = A1111 `localizations/*.json`, English text -> translation | Same file format: `LocalizationPack.parse` (BOM, limits: 16 MiB, 300,000 entries, key 4,096, value 16,384; non-string values counted and skipped) |
| Bilingual: translation and original together; Translation First / Original First | Settings > Language: *Translation only*, *Bilingual (two lines)*, *Bilingual (one line)*; *Translation first* / *Original first* |
| Compatible with language pack extensions, no re-import | Packs are found in `<app>/localizations`, `<app>/plugins-ext/NAME/localizations`, `<app>/extensions/NAME/localizations` and in folders the user lists (the folder itself, its `localizations` sub-folder, or an extension/A1111 folder). A later folder replaces an earlier pack of the same name (the helper script's `localizations[fn] = path` rule) |
| Dynamic translation of title hints | Tool tips (`Tooltip` of controls, tabs, `Tooltip.install`) are translated and re-translated when the application changes them; layout `translation\noriginal` as upstream |
| Placeholder text | Prompt texts of text fields / areas (`translation\n\noriginal` is impossible: JavaFX removes line breaks from prompt texts, so the two-line style uses `translation / original`) |
| Options of select boxes: `translation (source)` | Drop-down items (combo box cells; choice box converter): shown translated, the value/items are untouched |
| Regex rules `@@/regex/flags` with `$n` | Same; plus JavaScript's `$&` and `$$`; flags i, m, s, g (u/y accepted); a plain `@@text` is taken literally and unanchored as the extension does; each match is bounded (400,000 character reads, 1,024-character inputs, at most 2,000 rules) so a hostile pattern cannot freeze the UI |
| Scoped rules `##id##text`, `##@selector##text` | Same keys. `id` matches the JavaFX node id of the element or an ancestor; the selector supports type, `*`, `#id`, `.styleclass` compounds with descendant and `>` child combinators and comma lists; unsupported syntax (pseudo classes, attributes, `+`) drops that one rule with a warning |
| Numbers are not translated | Texts consisting of digits and dots are skipped |
| Ignore list (script/style/svg, model selectors ...) | `Localizer.skip(node)` / `skipTree(node)` markers; user text (text fields, text areas) is never touched, nor the values of combo boxes |
| MutationObserver (translate what the page adds later) | A listener on the text of every labeled control retranslates at once, and a 400 ms sweep (backing off when slow) catches new nodes and every other property; dialogs, popups and context menus are windows and are swept too |

Beyond the extensions: a **fallback pack** (selected pack first, then the second one), decoration-tolerant lookup
(`✎ Brush`, `Seed:`, `Open folder…` find `Brush`, `Seed`, `Open folder`), import of a pack file into `localizations/`
without overwriting, export of the English texts that have no translation as an empty pack, and the **download** dialog.

Two places compared tab/button text and are now language-independent: `MainWindow` (`--tab` option) and
`ImageBrowserTab.selectInner` use `Localizer.original(tab)` (the English title).

The engine, the MCP server and the PNG metadata are untouched: only displayed text changes, generation parameters
and saved files stay English (verified below). There is no MCP tool for the language because nothing an agent sends
or receives is localized.

## Assertions that were changed while writing the check, and why

Per the repository rule, these are stated plainly. No assertion of an existing check was touched.

- The first `verify` run compared every text after switching the language off with the text of the very first English
  snapshot and failed on five nodes (`No dataset selected`, `txt2img: 0 images`, `Updated 2026-... automatic updates ...`,
  two `VRAM estimate unavailable` lines). They are status labels of tabs that were built later or updated by the
  application while the Japanese UI was on, so the first snapshot was stale, not the restore. The assertion was
  replaced by two stronger ones that do not depend on application timing: (a) no Japanese text is left after switching
  off, and (b) a second on/off round trip reproduces exactly the same English texts. The five stale-baseline nodes are
  listed in the report line.
- After downloading, the check first waited for a result label starting with `Saved`; the label itself is shown in the
  active Japanese UI (`... を保存しました (Saved ...)`), so it now waits for the file name in the label and, in addition,
  checks that the three files exist on disk.
- Prompt texts cannot contain line breaks in JavaFX (`TextInputControl` strips them), so the planned
  `translation\n\noriginal` layout for text areas was removed from the design and from the test (`Prompt (プロンプト)` /
  `プロンプト / Prompt` are used).
- The first version of `LocalizerSuite` checked drop-downs through a wrapped `StringConverter`; the real window showed
  that the combo box button did not repaint on a language change, so combo boxes now use cells and only the choice box
  (one use, `ScrambleBatchPane`) keeps the converter. The choice box label is covered by the unit test of its
  converter, not by a screenshot.

## Not provided / limits

- **Translations of this application's own texts into languages other than Japanese.** Other languages work through
  the downloadable upstream packs, which cover 1.8 % to 18.2 % of the distinct texts of the window. That is why the issue
  is only partly done.
- Parts of the extensions that are HTML/CSS/JavaScript specifics: element ids and CSS rules of Gradio, `hints.js` titles,
  the `ignore_selector` list, the Devtools logger. Scoped keys written for Gradio ids (`##txt2img_...##`) never match a
  JavaFX node id; they are kept and harmless.
- Texts inside list, table and tree cells (gallery captions, table values, model card cells) and in drop-downs that
  have an application-defined cell (checkpoint and style boxes, model cards) stay English. Window titles of native
  file choosers belong to the operating system.
- Dynamic messages are translated only where a pack rule matches the whole message (the built-in pack has 28 pattern
  rules, e.g. `1 at once × N runs = M images`, `Done · N images`); progress lines with timings, error texts from the
  engine and exception messages stay English. `Done · 1 image` shows `完了 · 1 枚` only in the final pack; the screenshot
  `loc-real-window` was taken before that rule existed.
- A right-to-left or complex-script layout (Arabic, Thai) was not examined; the ar_AR and th_TH packs load and apply but
  their appearance was not looked at.
- The first sweep of a freshly built tab shows English for at most 400 ms for texts that are not labeled controls.
- Settings changes apply when OK is pressed; there is no live preview inside the dialog.
