## What was not checked

- The scala-torch backend still needs environment variables for the model (`SDFX_SCALATORCH_MODEL`), the tokenizer
  (`SDFX_SCALATORCH_TOKENIZER`), CUDA devices (`SDFX_SCALATORCH_UNET_DEVICE`, `..._VAE_DEVICE`) and, for SDXL, the memory
  caps (`..._UNET_MAX_BYTES`, `..._VAE_MAX_BYTES`, `..._MAX_ATTENTION_SCORE_ELEMENTS`). The package does not set them.
- `SDFX_SCALATORCH_JAVA` must be unset or point at `java.exe` itself, not at a directory.
- With a wrong `SDFX_SCALATORCH_JAVA`, a dry run persisted `vram_mode=cpu` into `settings.json`, which later made
  `set_model --dry-run` fail until the value was reset. The app should not write that value; not fixed in v0.2.
- Normal first-run setup (virtual environment and dependency download), the GUI generation path of the extracted
  package, and Python-engine generation with real checkpoints were not repeated for v0.2.
- Licences of converted annotator weights (Depth Anything, OpenPose, HED, MLSD, YOLOv8, NudeNet, U2-Net, aesthetic
  scorers, waifu2x, NormalBAE, Marigold) were not confirmed; none are bundled.
