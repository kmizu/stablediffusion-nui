Source: continue-revolution/sd-webui-animatediff `a88e88912bcbae0531caccfc50fd639f6ea83fd0` (ledger index 192, target `animatediff`). Its `LICENSE` is Creative Commons Attribution-NonCommercial-ShareAlike 4.0 (`licenses/continue-revolution__sd-webui-animatediff.txt`, SHA-256 pinned in `scripts/third_party.py`, label `CC-BY-NC-SA-4.0`). Only the README and `docs/how-to-use.md` / `docs/features.md` were read as the behaviour reference; no upstream code was read or copied. NUI re-implements the behaviour (`python/sdfx/animatediff.py`, `plugins/src/main/scala/sdfx/plugins/AnimateDiffPlugin.scala`) on diffusers' `MotionAdapter` (Apache-2.0). Note for users: the upstream extension is non-commercial; the NUI code is its own implementation, but the motion-module weights have their own terms (guoyww/animatediff and the diffusers adapters: Apache-2.0; conrevo/AnimateDiff-A1111: no licence declared). Weights are not bundled; the user downloads them.

## Design

- A txt2img / img2img **Script** `animatediff` (not AlwaysOn: it saves a video and a gallery image) plus an engine hook `animatediff` and a small engine request `animatediff_encode`.
- The motion modules are inserted into the loaded checkpoint's UNet at run time, as the extension does, with forward hooks: after every attention block (after the ResNet in blocks without attention) the matching temporal transformer of the adapter runs on the frames that sit on the batch axis. The checkpoint is not reloaded or copied; LoRAs and embeddings (PEFT adapters on that UNet) keep working. The hooks are removed after every run (also after a cancel) and the adapter is moved back to the CPU.
- The sampling loop is the engine's scheduler (any sampler the engine builds) over a 5-D latent `(1, 4, frames, h, w)`: per step each context window goes through the UNet (negative and positive prompt as two passes), noise predictions of windows are averaged per frame, then one scheduler step. Frames are VAE-decoded in chunks and go through the normal image pipeline (face restore / NSFW censor / saving), so every frame is a normal image with seed and infotext.
- Motion modules: original / A1111 files (`mm_sd_v14/v15`, `mm_sd15_v1/v2/v3`, ... `.safetensors` or `.ckpt`) are converted on load (key map `norms.0/1 -> norm1/2`, `ff_norm -> norm3`, `attention_blocks.0/1 -> attn1/attn2`, `temporal_transformer` dropped; layout read from the weights: block widths, layers per block, mid block yes/no, position table length), diffusers folders and Hugging Face repo ids (`guoyww/animatediff-motion-adapter-v1-5-2`). A bare file name is looked up in `$SDFX_ANIMATEDIFF_DIR`, `<models>/AnimateDiff`, `animatediff`, `motion_module`. A module for the wrong family (SD 1.x module with an SDXL checkpoint) is rejected from the layer counts.
- **Linear beta schedule**: the scheduler is built with `beta_schedule=linear` (the schedule AnimateDiff was trained with; diffusers' AnimateDiff examples use it too) instead of the checkpoint's scaled-linear one. Without it the frames come out grey and washed out (the "grey issue" the extension's README thanks its contributors for fixing); the control `Linear beta schedule` (hook key `linear_betas`, default on) switches it off, and the verification run below measures the difference.
- Settings of the extension (names as in its API): number of frames (`video_length`, 0 = context batch size), `fps`, `loop_number`, `closed_loop` (N / R-P / R+P / A), context `batch_size` (1..32), `stride`, `overlap` (-1 = batch_size / 4), Img2Vid `latent_power` / `latent_scale` / `last_frame` / `latent_power_last` / `latent_scale_last`, FreeInit (filter, d_s, d_t, n, iterations), save formats GIF / MP4 / WEBP / WEBM / PNG / TXT. Prompt travel: head lines, `frame: prompt` lines (ascending, below the number of frames), tail lines; each keyframe prompt is head + keyframe + tail and the conditioning is interpolated linearly per frame (R+P and A also interpolate from the last keyframe back to the first).
- Context windows (frames > context batch size): uniform sliding windows of the context size with the given overlap (the last window is shifted to end at the last frame); for each motion stride 2^i <= Stride the frames 2^i apart (each offset) form their own groups; closed loop adds wrap-around windows (R-P / R+P: one centred on the seam; A: a ring of windows around the whole video). Every frame is covered; overlapping predictions are averaged. A video that fits one context is one window (stride, overlap and R modes have nothing to do; A appends the reversed frames without the two end frames when encoding).
- Img2Vid (img2img tab): frame i starts from `init * a + noise * (1 - a)` with `a = 1 - i^power / scale` clamped to [0, 1] (the documented formula); with a last frame the mirrored weight `1 - (F-1-i)^power_last / scale_last` is added (normalised when the two exceed 1); the usual img2img strength then noises and truncates the schedule.
- FreeInit (txt2img): after the first full denoise the result is re-noised to the first timestep with fresh Gaussian noise, its low frequencies (3-D FFT over frames x height x width, butterworth / gaussian / box / ideal low-pass) are kept and the high frequencies come from another fresh noise, then it is denoised again (`iterations` passes in total).
- Output: first frame saved to the gallery with the infotext (`AnimateDiff: "{'model': ..., 'video_length': 16, 'fps': 8, ...}"`, the Python-dict spelling of the extension, plus a `format` list); GIF / WEBP (Pillow, frame delay in 10 ms steps for GIF) / MP4 (libx264, yuv420p, CRF 18) / WEBM (VP9) next to it with the same stem; PNG saves every other frame to the gallery too; TXT writes the infotext. MP4 / WEBM need ffmpeg on PATH. Videos are plaintext files, so the image-scrambling session must allow plaintext video (like SVD).
- Replay: GUI (PNG restore selects the script and fills the form), MCP `inspect_generation_metadata` (script candidate `animatediff`), the extension's own infotext dict restores too.

## Not provided

- Frame interpolation (FILM) needs the Deforum extension: `interp` other than Off is rejected.
- ControlNet V2V (video source / video path / mask path, batch control images, keyframes), SparseCtrl, IP-Adapter prompt travel: a request with ControlNet units is rejected.
- Motion LoRAs (`mm_sd15_v2_lora_*`) and the V3 domain adapter: LoRA tags for them are not applied to the motion modules.
- Hotshot-XL spelling of the SDXL motion module (the diffusers `animatediff-motion-adapter-sdxl-beta` layout is used); SD2 / SDXL-inpaint / inpaint checkpoints are rejected.
- Batch size above 1 (use the batch count: one video per iteration), Hires. fix, img2img Hires fix, Model Keyword, inpainting masks, FreeInit in img2img are rejected with a message. Per-pass UNet hooks of other plugins (FreeU, PAG, LLuL, ...) are not applied to the video: a warning lists them.
- X/Y/Z axes, the A1111 settings page (gifsicle / palette optimisation, WEBP quality, output folder, "save frames to the original output folder"), audio.
- The upstream GroupNorm treatment of the V1/V2 modules is not reproduced: the diffusers port (joint GroupNorm over frames inside the motion modules, per-frame in the UNet) is what runs; with the linear schedule the frames are vivid, so nothing grey is left to fix here.
- Position tables: files of the original format get the original sinusoid (verified equal to `pos_encoder.pe`). The Hub's SD 1.x diffusers adapter `guoyww/animatediff-motion-adapter-v1-5-2` stores its `pos_embed.pe` buffers in another layout (all sines, then all cosines); with those the frames came out grey (contrast 24 against 50, same seed and prompt), so every non-file adapter has its tables rebuilt to the original layout on load (`reset_position_tables`). After that the diffusers folder and the original file hold the same weights and give byte-identical frames. The SDXL beta adapter already stores the original layout (checked: difference 2e-4, fp16 rounding), so for it the rebuild changes nothing.
- Memory: the SDXL module is run with 4 frames at 832x1216 here because the checks share a 24 GB card (8 frames at that size spilled into system memory and did not finish in 20 minutes). SD 1.x runs 16 frames at 512x512 easily.

## Verification

Environment: Windows, RTX 3090 (24 GB, shared with other jobs: some runs below were very slow because of that), diffusers 0.33.1, torch 2.7.1+cu128, ffmpeg from WinGet. Motion modules: `mm_sd15_v2.safetensors` and `mm_sd15_v3.safetensors` (conrevo/AnimateDiff-A1111, original format), `guoyww/animatediff-motion-adapter-v1-5-2` (diffusers folder), `guoyww/animatediff-motion-adapter-sdxl-beta` (diffusers folder). None is bundled.

- **Python** (torch CPU, tiny UNets, `python/tests/test_animatediff.py`, 34 tests): settings and bounds, FILM rejection, prompt travel parsing / interpolation / loop, context windows (coverage of every frame, overlap, stride groups, closed-loop wrap windows), ping-pong, GIF / WEBP / MP4 / WEBM encoding, model resolution, **the hooks reproduce diffusers' `UNetMotionModel.from_unet2d` output to 1e-5** (with and without a mid block, 2 and 3 levels), layout mismatch rejection with the hooks removed, original-format to diffusers key conversion round trip, Hub position tables rebuilt, FreeInit filters / frequency mixing, Img2Vid weights, the whole loop (determinism, frame count, motion vs a zeroed adapter, long videos in all four closed-loop modes, prompt travel encodes every keyframe, FreeInit adds passes, Euler / CFG 1, cancel, context larger than the module, an SDXL-shaped UNet with added conditioning, family mismatch, scoped linear-beta override, unapplied-hook warning). Full Python suite (`pytest python/tests`, CUDA hidden): 0 failures, 2 skipped.
- **Scala**: `AnimateDiffSuite` (12: registration, defaults, bounds, hook values, infotext dict round trip and the extension's own text, run on the fake host: frames, first-frame gallery image, videos beside it, PNG frames, one video per batch count, img2img kind, option errors before any generation, interrupt, plaintext-video policy), `InspectGenerationMetadataSuite` AnimateDiff case, `AnimateDiffReplaySuite` (GUI restore), `NativePresetsCoverageSuite` (ledger = registry).
