# v0.26 verification record (2026-11-12)

Two things: a comparison with a PyTorch engine on the same machine, and the failure on PCs where cuBLAS is not found.
scala-torch `0.1.3-gh47`. All numbers: RTX 3090, MCP, fp16, 20 steps, Euler a, second generation in the same process, on an extracted
ZIP (path with a space).

## Comparison with PyTorch on the same machine

reForge itself is not started in this project. NUI's own Python engine was used instead: diffusers 0.33.1 on PyTorch 2.7.1 (CUDA 12.8,
cuDNN 9.7), which uses the same building blocks as reForge (cuDNN convolution, PyTorch's scaled dot product attention, one U-Net batch
for a batch size). Both engines were started from the v0.25 package with the same requests, alternately, two rounds; scala-torch with
cuDNN from the same PyTorch installation.

| Request | PyTorch engine | scala-torch v0.25 |
| --- | --- | --- |
| SD1.5 512, 1 image | 1.3 / 1.3 s, 3.6 GB | 1.8 / 1.9 s, 2.4 to 2.6 GB |
| SD1.5 512, 1 image, 40 steps | 2.5 / 2.4 s | 3.1 / 3.4 s |
| SD1.5 512, batch size 4 | 4.0 / 4.0 s, 7.0 GB | 4.5 / 5.2 s, 3.0 GB |
| SD1.5 512, batch size 8 | 8.0 / 9.1 s, 11.9 to 12.2 GB | 8.1 / 9.1 s, 3.4 GB |
| SDXL 1024, 1 image | 6.8 / 7.6 s, 15.9 to 16.3 GB | 7.7 / 9.5 s, 9.8 GB |
| SDXL 1024, batch size 2 | 13.7 / 74.3 s, 21.5 to 22.9 GB | 14.3 / 16.7 s, 8.6 to 9.5 GB |

- Batch size 8 for SD1.5 takes the same time in both engines. Batch size 4 and SDXL are 5 to 25 % slower in scala-torch; a single
  SD1.5 image is 40 % slower (about 0.5 s).
- scala-torch uses a third to a half of the memory. The PyTorch engine ran out of the 24 GB in the second round of SDXL batch size 2
  (22.9 GB used, 74.3 s).
- The second round was slower for both engines (other programs were using the machine).
- From the 20 and 40 step rows: a step of a single SD1.5 image costs about 57 ms in PyTorch and about 72 ms in scala-torch, and the
  time outside the steps is about 0.15 s against about 0.35 s.

This is not a measurement of reForge. reForge has its own sampler loop and memory management, so its numbers can differ from
diffusers' in both directions.

## cuBLAS not found

Float16 needs cuBLAS, which is not in the ZIP. It was looked for on the search path and in `CUDA_PATH` only. Where neither had it, a
generation failed in the middle with "broadcast add needs one element type".

- cuBLAS is now also looked for in the cuDNN folder (`SCALATORCH_CUDNN_PATH`, Settings > scala-torch cuDNN folder; a PyTorch
  `torch\lib` holds cuBLAS too) and in every CUDA Toolkit under Program Files.
- Environment variable names are matched without regard to case. A first build looked for `ProgramFiles` only; started from Python,
  which passes `PROGRAMFILES`, it found nothing and ran in Float32 (26 s). Found on the package before the release.
- When cuBLAS cannot be loaded at all, the model runs in Float32 and one line says what is missing and what to do.
  `SCALATORCH_CUDA_LIBRARY_LOG=1` prints why each candidate failed.

Measured on the v0.26 package (SD1.5 512 unless stated):

| Case | v0.25 | v0.26 |
| --- | --- | --- |
| Toolkit removed from `Path` and `CUDA_PATH` (still under Program Files) | fails | 1.9 s (SDXL 9.1 s) |
| the same, cuDNN folder given | not measured | 1.8 s |
| cuBLAS switched off (`SCALATORCH_CUDA_CUBLAS=0`) | fails | 26.1 s in Float32, 5.2 GB, with the note |

Float32 without cuBLAS is slow (SDXL 1024 took 252 s in the development build). It is a way to get an image at all, not a mode to work
in.

## Other checks on the package

With cuDNN: SD1.5 1 image 1.8 s, batch size 8 8.1 s; SDXL 7.9 s, batch size 2 14.9 s (as v0.25). SDXL at a limit of 4000 MB: 20.0 s,
3.6 GB, first and second image pixel-identical to the unlimited image. No request failed.

## Tried and not used

Choosing the cuDNN algorithm by measurement (`cudnnFindConvolutionForwardAlgorithm`) instead of cuDNN's heuristic: the same generation
time (SD1.5 40 steps 3.3 to 3.4 s, SDXL 9.0 to 9.5 s either way) and 2.5 to 3 s more for the first generation. Available with
`SCALATORCH_CUDNN_MEASURE=1`, off by default.

## Tests

- `CudnnSuite`: the cuBLAS candidate order (search path, cuDNN folder, `CUDA_PATH`, Toolkits under Program Files newest first) and
  variable names in another case, for cuBLAS and cuDNN. No GPU needed.
- `ffm` `testFull` on the GPU with cuDNN: 95 total, 93 passed, 2 skipped.

## Not covered

- A PC that really has no CUDA Toolkit was not used; the cases above remove the Toolkit from the variables or switch cuBLAS off.
- reForge was not run. The GUI was not used. No GPU with less than 24 GB.
- cuBLAS is still not shipped in the ZIP.
