# v0.24 verification record (2026-11-12)

Goal: use what the papers offer to cut the work per image, on top of the kernel work. scala-torch `0.1.3-gh44`.
All numbers: RTX 3090, MCP, fp16, 20 steps, Euler a, second generation in the same process, cuDNN from a PyTorch installation, on the
extracted ZIP (path with a space). v0.23 and v0.24 were measured in the same run.

## What was wrong

A request with the CFG Schedule plugin left both fast paths (guidance as one U-Net batch, batched sampling of a batch size) and became
slower, not faster: on v0.23 SDXL 1024 took 9.6 s instead of 8.6 s and an SD1.5 batch of 8 took 18.5 s instead of 9.6 s. A step whose
scheduled guidance was 1 still ran the negative pass.

## Change

The batched predictor takes the scheduled guidance. At exactly 1 the result is the positive prediction, so only the positive pass runs.
Batched sampling accepts the `cfg_schedule` hook (and, since v0.23, `deepcache`). This is how "guidance in a limited interval"
(Kynkäänniemi et al., arXiv 2404.07724) and the late-step part of Adaptive Guidance (Castillo et al., arXiv 2312.12487) can be used:
CFG Schedule with CFG at start 7, CFG at end 1, begin 0.69, finish 0.7 keeps guidance for the first 70 % of the steps.

No request failed; the file counts were right (2, 16, 2 and 4 files for two requests each).

Images (same seed, SDXL, development build, looked at side by side): guidance until 70 % is nearly the same image as full guidance;
until 50 % it is clean but the colours follow the prompt less (the yellow eyes turn grey); with DeepCache on top it is softer.
The images of v0.24 differ in fine detail from v0.23 with the same schedule (mean difference 2.4 of 255), because the steps now run on
the batched path.

## Tests

- `CudaUNetSuite` "a scheduled guidance on the batched path matches the CPU predictor": targets 1, 3, 0.5 and 7.5 against the CPU
  predictor (Float32, tiny U-Net, largest error 6.1e-6), and at 1 the result equals a run without a negative prompt (< 1e-6).
- The test that expected a batch with a schedule to be refused now checks that it runs and equals the run without a schedule.
- Touched `models` suites: 23 total, 17 passed, 5 skipped, 1 failed (the `CudaUNetSuite` budget test that fails without this change).

## Not covered

- Only a guidance of exactly 1 saves the negative pass; other values run both passes as before.
- The CFG schedule with batched sampling was run for Euler a only, and compared by eye, not in Float32 against the sequential path.
- The GUI was not used. No GPU with less than 24 GB.
- From the papers, still not implemented: AdaptiveDiffusion (skipping whole U-Net evaluations, 1.6x to 2.0x at 50 steps) and a fast
  token downsampling (the existing plugin is slower than no plugin).
