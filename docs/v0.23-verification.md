# v0.23 verification record (2026-11-12)

Goal: a large gain in generation speed, with the batch case handled the way reForge handles it. scala-torch `0.1.3-gh43`.
All numbers: RTX 3090, MCP, fp16, 20 steps, second generation in the same process, cuDNN from a PyTorch installation
(`SCALATORCH_CUDNN_PATH`), on the extracted ZIP (path with a space) unless stated. v0.22 and v0.23 were measured in the same run.

## Changes

1. **DeepCache works with a batch.** With a batch size of 4 every image after the first failed with "tensor belongs to another CUDA
   session" (the cached features belonged to the first image's session). A rising timestep now starts a new sampling. DeepCache also
   runs together with batched sampling (one U-Net batch for all images).
2. **cuDNN picks the algorithm.** The convolution algorithm comes from cuDNN's own ranking for each shape instead of one fixed
   algorithm. The fixed one took 16 ms for 16 x 1280 x 32 x 32 and 5.8 ms for a convolution to 4 channels.
3. **1x1 convolutions of a batch go through cuDNN.** The built-in path called cuBLAS once per sample: 29,488 calls in 40 U-Net passes of
   an SD1.5 batch of 8.
4. **Softmax reads the score matrix once** (rows of 2048 to 4096 keys): attention `[16,4096,40]` 3.50 -> 3.08 ms, `[20,4096,64]`
   4.52 -> 3.86 ms.
5. Linear layers add their bias inside the matrix product. No measurable change.

## Measured

| Request | v0.22 | v0.23 | v0.23 with DeepCache (interval 3) |
| --- | --- | --- | --- |
| SD1.5 512, 1 image | 2.0 s | 2.1 s | 1.6 s |
| SD1.5 512, batch size 4 | 5.9 s | 5.6 s | 4.6 s (v0.22: fails) |
| SD1.5 512, batch size 8 | 11.4 s | 10.2 s | 8.6 s |
| SDXL 1024, 1 image | 9.1 s | 9.1 s | 5.4 s |
| SDXL 1024, batch size 2 | 16.9 s | 16.8 s | 10.0 s |

Without DeepCache the gain is in the SD1.5 batch only (batch size 8: 10 %). DeepCache with interval 3 and 5 full steps first brings SDXL
to 59 % of the time. In the development build, interval 5 with 3 full steps first gave SDXL batch size 2 in 8.9 s (18.9 s without).

DeepCache changes the image. Same seed, SDXL, looked at side by side: interval 3 keeps the composition and is a little softer;
interval 5 loses fine detail visibly (the ribs of a knitted sweater are gone). DeepCache is a plugin and off by default.

For SD1.5 DeepCache helps less than the paper's 2.3x: the blocks it keeps running are the 64 x 64 ones, and their self-attention is
where this engine spends most of its SD1.5 time.

VRAM limits (SDXL, cuDNN): the first and the second image at 8000 MB (10.3 s, 7.2 GB) and 4000 MB (19.7 s, 3.5 GB) are pixel-identical
to the unlimited image (8.7 s, 7.5 GB).

## Tried and not used

- **Attention without a score matrix (tensor cores, WMMA).** Two kernels were written and are correct (compared with Float32 for widths
  16 to 160, different key and query counts, large scores). Both are slower than the cuBLAS path: `[20,4096,64]` 17.0 ms and 21.3 ms
  against 3.9 ms; `[16,4096,40]` 6.2 and 10.4 ms against 3.1 ms. The second shares the key and value tiles between eight warps of a block
  to cut memory traffic and was slower still, so the limit is the trip through shared memory for the exponentials of every 16 x 16 tile.
  The first kernel is kept behind `SCALATORCH_CUDA_FUSED_ATTENTION_HALF=1`.
- **Softmax with a per-thread array of 32 values**: twice as slow (the array lands in local memory). The version in use keeps 16 values
  in registers.
- **Token downsampling (ToDo) as it is now**: slower, not faster (SD1.5, 40 steps: 3.3 s -> 7.5 s; SDXL: 10.1 s -> 12.4 s), because a
  request with it leaves the fast paths. Not changed in this release.

## From the papers

- DeepCache (Ma et al., CVPR 2024, arXiv 2312.00858): in use, see above.
- AdaptiveDiffusion (Ye et al., NeurIPS 2024, arXiv 2410.09873): skips the U-Net on steps where the third-order difference of the latent
  is small; 1.6x to 2.0x for SD1.5 and SDXL at 50 steps. Not implemented; its gain at 20 steps is not known.
- Guidance in a limited interval (Kynkäänniemi et al., arXiv 2404.07724) and Adaptive Guidance (Castillo et al., AAAI 2025,
  arXiv 2312.12487): no guidance pass on part of the steps, about 25 % fewer U-Net evaluations in the latter. Not implemented.
- T-GATE (Liu et al., arXiv 2404.02747): caches cross-attention after it converges, 10 to 50 %. Cross-attention is a small part of the
  time here (77 keys), so the gain would be small.

## Tests

- scala-torch: `DeepCacheSuite` "a rising timestep starts a new sampling"; `CudaHalfSuite` gets the fused attention shapes and the linear
  layer with bias. `ffm` `testFull` on the GPU with cuDNN: 93 total, 91 passed, 2 skipped. `CudaHalfSuite` with the fused kernel switched
  on: 15 of 15.
- Touched `models` suites: 22 total, 16 passed, 5 skipped, 1 failed (the `CudaUNetSuite` budget test that fails without this change too).

## Not covered

- DeepCache with batched sampling was run for Euler a only.
