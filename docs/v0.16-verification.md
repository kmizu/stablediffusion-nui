# v0.16 verification record (2026-11-10)

## "Failed: [invalid_params] requirement failed: CUDA session allocation budget exceeded"

Reproduced on the v0.15 package: SDXL `waiIllustriousSDXL_v170` 1024x1024 fp16 with the LoRA `20_cat-hinomina` (weight 0.8) failed on both runs
with this message although the GPU (24 GB) was nearly empty (the job needed about 9 GB at the point of failure).

Cause: every CUDA session is given a fixed memory budget (the app set 8 GiB for the U-Net and 8 GiB for the VAE, 18 / 12 GiB for fp32). Anything that
needs more than the budget fails, whatever the GPU has free: SDXL with a LoRA (the LoRA is merged into a second half-precision copy of the weights, 5.1 GB +
5.1 GB), ControlNet on SDXL, fp32 SDXL, big images, hires passes.

Fix (scala-torch `0.1.3-gh35`): the budget can be `auto`: 92 % of the device memory that is free when the session opens (at least 256 MiB).
`SDFX_SCALATORCH_UNET_MAX_BYTES` / `_VAE_MAX_BYTES` accept `auto`, and the app now uses `auto` by default (an explicit value still wins). A request
that really does not fit the GPU still fails, but with the GPU's own limit instead of an arbitrary one.

Checks: scala-torch `CudaHalfSuite` (AutoBudget gives a budget between 256 MiB and the free memory; a 1 KiB budget still rejects an allocation; `auto`
parses), `ScalaTorchLaunchSuite` (defaults `auto` for fp16 and fp32, explicit value wins), engine / mcp / ui suites.
Real check on the extracted v0.16 ZIP (RTX 3090, MCP, clean environment):

| Case | v0.15 | v0.16 |
| --- | --- | --- |
| SDXL 1024x1024 fp16 + LoRA | **failed (budget exceeded)** | 18.4 s, job memory 13.6 GB, LoRA effect visible in the image |
| SDXL 1536x1536 fp16 + LoRA | (failed) | 27.0 s, job memory 14.1 GB |
| SDXL 1024x1024 fp32, 12 steps | failed in v0.13 with the 8 GiB default | 25.7 s, 13.2 GB |

Not covered: ControlNet on SDXL, SDXL hires fix (same mechanism, not run), GPUs with less than 16 GB (the jobs above need 13-14 GB with a LoRA).
