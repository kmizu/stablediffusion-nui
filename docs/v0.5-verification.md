# v0.5 verification record (2026-11-09)

`prompt_generator` (#101) now runs a real GPT-2 model on the JVM (`plugins/.../Gpt2.scala`, own implementation of the published GPT-2
architecture: byte-level BPE tokenizer, safetensors reader, 6/12-layer transformer with KV cache; no Python, no torch, no new dependency).
The Markov-chain method from v0.3 stays as a second method.

- **Model files are not bundled.** Point "GPT-2 model folder" at a Hugging Face folder with `model.safetensors` (F32), `vocab.json`,
  `merges.txt`, `config.json`. Tested with `distilbert/distilgpt2` (Apache-2.0), downloaded with `hf download`; promptgen-style
  fine-tunes of GPT-2 that are stored in F32 should load the same way (not tested: F16 weights are rejected with a clear error).
- **Exactness**: against transformers 4.51 (`GPT2LMHeadModel` / `GPT2TokenizerFast`) the tokenizer ids match on a punctuation / apostrophe /
  unicode / emoji string, the last-position logits give the same top-5 ids with logit -20.885 within 0.01, and greedy 12-token
  continuation is identical (`Gpt2Suite`; skipped automatically when the model folder is missing).
- **Speed**: about 1.3-1.7 s for prompt + 12 greedy tokens on the CPU (single thread, F32).
- **GUI**: `RealPromptToolsCheck` (real `MainWindow`, scala-torch, RTX 3090): the GPT-2 method generated 2 SD1.5 images whose prompts
  start with the base prompt and continue it (e.g. "1girl, silver hair, upper body and head"); images viewed. Plain distilgpt2 is not
  tuned for Stable Diffusion prompts, so its continuations are generic English; fine-tuned prompt models give better text.
- Not covered: the promptgen extension's own model downloader / model list UI, GPT-2 weights in F16/BF16, GPU inference.
