# ControlNet Fastload verification (#17)

Source: pk5ls20/sd-webui-controlnet-fastload `bbdb929f4285ea69d5099268496e4322dc7203ab` (Apache-2.0), with ControlNet behaviour read from Mikubill/sd-webui-controlnet `56cec5b2958edf3b1807b7e7b2b1b5186dbd2f81`. Both were read as references only; nothing was imported or launched. NUI re-implements the behaviour.

## What NUI provides

- AlwaysOn plugin `controlnet_fastload`: Load only, Save only, Load & Save; Current first (an enabled current unit wins and the file is not read) or Loaded first; save as an appended trailer, a `.cni` sidecar, or both. Saved files use the upstream marker + gzip + pickle layout (protocol 3, dict units with NumPy images), so upstream can read them. NUI reads files with a bounded symbolic pickle interpreter and never executes pickle.
- Inspect, preview, send-to-unit and capture in the ControlNet Fastload tab; browse, filter (36 per page) and send in the gallery tab; `controlnet_fastload` MCP tool for version/inspect; generation-time load/save from MCP through `always_on`.
- Native ControlNet gains the upstream unit settings Fastload files carry, so loaded units apply instead of being rejected:
  - control mode: "My prompt is more important" scales residual i by 0.825^(12-i) (SDXL keeps the first 10 scales, as upstream). "ControlNet is more important" also zeroes the unconditional samples (CFG layout [uncond, cond], PAG [uncond, cond, perturbed]). Balanced units are untouched, so existing native output is unchanged.
  - canny processor resolution and pixel perfect, using upstream's pad-to-64 resize and default thresholds 100/200 and resolution 512. none and invert ignore these settings, as upstream does.
  - hires passes soften canny and MLSD units that use ControlNet-compatible processing (all units loaded from upstream files), as upstream forces in hires fix.
  - an ordinary (non-inpaint, non-CLIP) mask selects the RGB source when it is wholly at most 5 or at least 250, otherwise the mask scribble, with upstream's alpha-over-white compositing.
- Settings with no effect on ordinary output are accepted: `low_vram` (device placement), `save_detected_map` (UI preview only), UI flags and the default values of modern batch, union, IP-Adapter, region-mask and AnimateDiff fields. They are preserved when NUI re-saves the loaded units.
- Rejected with the setting names, never silently dropped: inpaint/CLIP masks, batch inputs, non-default advanced weighting or region masks, `hr_option` other than Both, processor resolution or pixel perfect for preprocessors other than none/invert/canny, more than three units, and preprocessors the engine does not have.
- Upstream `[hash]` suffixes in model names resolve to the catalog entry. The new `list_controlnets` MCP tool lists ControlNet models, preprocessors and control modes.

## Acceptance evidence (2026-11-01)

- Real models through the official MCP Python SDK 2.3.0 over stdio, driving the real Scala generator and Python engine (`scripts/dev/check_fastload_real.py`, receipts in `outputs/claude-fastload-real-{sd15,sdxl}/receipt.json`). SD1.5 `animekawa_v10` 512 px with `lllyasviel/control_v11p_sd15_canny` and SDXL `waiIllustriousSDXL_v170` 768 px with `diffusers/controlnet-canny-sdxl-1.0`; both passed every assertion:
  - an upstream-format `.cni` (900x600 NumPy image, model `name [hash]`, pixel perfect, all modern fields) loads and changes the output; the three control modes give three different images;
  - Load & Save with both formats reproduces the load-only image exactly, the output has one trailer plus a `.cni`, inspection reports no unapplied setting, and reloading either copy reproduces the image exactly;
  - Save only captures a native typed unit ("ControlNet is more important", pixel perfect) and loading that output with no current unit reproduces it exactly;
  - Current first keeps the current unit; Loaded first uses the file (both pixel-exact);
  - a hires pass with a loaded canny unit completes;
  - cancelling a Load & Save job leaves no new file, and the next generation reproduces the load-only image exactly.
- The same checks passed again for SD1.5 and SDXL through `SDNUI.exe --mcp` from the extracted v0.04 package (receipts `outputs/claude-v004-real-{sd15,sdxl}`), after the review fixes. The package's 269 tracked Python, model and licence files, jar and notices matched the source byte for byte.
- Images inspected on contact sheets. All loaded units follow the circle, square and line, cropped by Crop and Resize. On SD1.5 "My prompt is more important" is visibly prompt-led and "ControlNet is more important" has the strongest edges. On SDXL both non-Balanced modes weaken the structure strongly; the native "ControlNet is more important" capture looks the same. This follows from upstream's SDXL scale truncation (early residuals x0.1 to x0.3) rather than an NUI-specific path, but it was not compared against a running upstream WebUI.
- CPU tests: the source canny output equals an independent restatement of the pinned resize/pad/canny code at three resolutions; pixel-perfect and default-resolution rules; residual hooks for SD1.5/SDXL soft scales, per-unit CFG masking (CFG, PAG and no-CFG layouts), Balanced units unhooked, hires softening only for compatible canny/MLSD, Neutral Prompt and odd batch rejection, and hook removal.

## Limitations

- NUI does not write A1111-style `ControlNet N:` infotext, so gallery filters list choices only for images whose metadata has it (A1111/Forge outputs); NUI outputs appear unfiltered.
- `inpaint_crop_input_image` is accepted but NUI does not crop ControlNet inputs to the img2img "only masked" region as upstream does.
- Inpaint and CLIP masks, batch inputs, hires-only/low-res-only units and other preprocessors' resolution settings are rejected rather than applied.
- Readable legacy data is never written in protected (scrambled) sessions; Load only still works there.
- Interoperability was shown with files written by NUI's writer in upstream's format and with fixtures produced by the pinned upstream classes and writer, not with files saved by a running A1111/Forge.
