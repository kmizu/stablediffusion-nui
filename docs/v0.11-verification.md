# v0.11 verification record (2026-11-10)

## scala-torch backend without environment variables

Until v0.10 the bundled scala-torch backend needed `SDFX_SCALATORCH_MODEL`, `_TOKENIZER`, `_UNET_DEVICE`, `_VAE_DEVICE`, `_UNET_MAX_BYTES`,
`_VAE_MAX_BYTES` and `_MAX_ATTENTION_SCORE_ELEMENTS` (and a wrong `SDFX_SCALATORCH_JAVA` crashed the launch). That contradicted the
all-in-one goal. v0.11 removes the need:

| Was a variable | Now |
| --- | --- |
| model | last used checkpoint (else the first checkpoint) from the model folders or `<home>/models/Stable-diffusion`; no checkpoint gives a message that names the setting |
| tokenizer | CLIP `vocab.json` / `merges.txt` bundled in `scala-torch/tokenizer` (notice added to THIRD_PARTY_NOTICES.md) |
| devices | new default `auto`: CUDA when an NVIDIA driver is present, else CPU (a saved `cpu`/`cuda` choice is kept) |
| memory caps | 8 GiB U-Net / VAE and 2^30 attention-score elements unless set |
| Java / worker | found from the install folder (`<install>/scala-torch`) even when `--home` points elsewhere (MCP) |
| `SDFX_SCALATORCH_JAVA` | no longer selects the backend by itself; a folder value is accepted (it looks for `java.exe` inside); the native fp32/cpu forced values are no longer written to settings.json |

The packaged app now starts on the scala-torch engine (`-PreferScalaTorch`); the Python engine stays selectable in Settings.

Checks: `ScalaTorchLaunchSuite` (zero-configuration launch, last model / first model, device and cap defaults, explicit values win, java folder,
no checkpoint -> error), `scalaTorchEngine`, `engine` and `mcp` test suites. Real check of the **extracted ZIP** (`C:\tmp v011x\`, path with spaces),
MCP over stdio with the bundled Java, **no `SDFX_*` environment variable**, settings.json only holding the model folder and the engine choice (what the
settings dialog writes): `set_model` + `txt2img` on SD1.5 `animekawa_v10` 512 px / 20 steps and SDXL `waiIllustriousSDXL_v170` 1024 px / 20 steps
both succeeded on `cuda:0` and the images were viewed. `PixelScrambleSuite` fails on this machine only because `python/.venv-test` is missing (not related).

## Image Browser: in-app video preview (#142)

Selecting a video in the Image Browser now shows an in-app preview (JavaFX Media): first frame, Play/Pause and a seek bar; undecodable files show
a message and keep "Open video". Real GUI check `RealVideoPreviewCheck` (H.264 mp4 made with ffmpeg from real generations): preview ready (2.0 s, 512x512),
Play advances the clock 1 ms -> 2000 ms, selecting a still image hides the video pane, a corrupt .mp4 shows the fallback message.
Not covered: formats other than what the JavaFX decoder supports (H.264/AAC mp4/m4v, and similar), audio output device selection.

## Python engine

Not removed. It still carries the extension features that were verified only on it, and the native engine has no dry-run; the replacement list
is tracked in `docs/SCALATORCH-COVERAGE.md`.
