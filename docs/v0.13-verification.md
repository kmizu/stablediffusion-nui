# v0.13 verification record (2026-11-10)

## scala-torch: fp16 (and fp32) selectable per model

Finding: scala-torch already ran CUDA execution in half precision internally (since 7ca120d; `SCALATORCH_CUDA_FP16=0` switched it off), but the
worker's `load_model` rejected everything except `dtype=fp32` with `vram_mode=cpu` ("native parameter loading requires fp32 and cpu"), so the
app could neither ask for fp16 nor for fp32, and a saved fp16 setting produced that error.

Changes (scala-torch `0.1.3-gh33`, commit f27fe72 on `fix/clip-position-ids-float-dtype`, published to `maven-repo`):
- `load_model` accepts `dtype` = `fp16` (default, also `half` / `float16` / `auto`) or `fp32` (`float32` / `full`), applies it to U-Net, VAE and CLIP
  (`CudaDiffusionRuntime.fp16Default` now follows the loaded model), and reports the dtype in the model summary; `vram_mode` is accepted and ignored;
  `bf16` and anything else is rejected with "native engine supports dtype fp16 and fp32". CPU execution stays Float32 whatever is asked.
- NUI sends the Settings precision (`fp16` / `fp32`; `bf16` is sent as `fp16`, there is no bf16 in the native engine) and no longer forces fp32 / cpu.
- Default CUDA memory budgets depend on the precision: fp16 8 GiB / 8 GiB, fp32 18 GiB (U-Net) / 12 GiB (VAE) (fp32 SDXL did not fit in 8 GiB:
  "CUDA session allocation budget exceeded").

Measured on the extracted v0.13 ZIP (RTX 3090, 24 GB, MCP, clean environment, Euler a, 20 steps, seed 173, second run = warm; GPU memory is the whole
GPU's `memory.used` peak, about 3.9 GB of it belonged to other programs):

| Model | dtype | Time per image | Peak GPU memory | Mean abs pixel diff to fp32 |
| --- | --- | --- | --- | --- |
| SD1.5 `animekawa_v10` 512x512 | fp16 | **7.7 s** | 7.1 GB | 1.0 / 255 |
| SD1.5 | fp32 | 11.4 s | 9.1 GB | - |
| SDXL `waiIllustriousSDXL_v170` 1024x1024 | fp16 | **20.3 s** | 12.0 GB | 2.2 / 255 |
| SDXL | fp32 | 45.4 s | 17.2 GB | - |

The fp16 and fp32 images were viewed side by side: same composition and details (small differences in fine texture). fp16 is 1.5x faster on SD1.5,
2.2x faster on SDXL and needs 2 to 5 GB less memory.

Checks: scala-torch `NativeDiffusionBackendSuite` new test (fp16 / fp32 accepted and reported, bf16 rejected; run with the tiny model fixture; one
older test in that suite, the sampler-name order check, already failed before this change); NUI `EngineBackendSelectionSuite`, `ScalaTorchLaunchSuite`
(fp32 budgets), engine / mcp / ui suites.
Not covered: bf16, fp16 on the CPU path (stays fp32), fp16 with every plugin (LoRA is merged into half weights as before), the first-run GUI flow.
