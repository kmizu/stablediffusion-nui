# Img2Img のフォルダ入力（開発中）

Img2Img の「Img2Img folder」でフォルダ処理を有効にして入力フォルダを選ぶと、フォルダ直下の画像を名前順に処理する。サブフォルダには降りない。対応拡張子は PNG、JPEG、WebP、BMP、TIFF。入力画像は書き換えず、出力は通常の Img2Img 出力先に保存する。現在のプロンプト、生成設定、Script、AlwaysOn 拡張が各画像に適用される。WD v3 batch とは同時に使えない。

ジョブの開始時に入力を一覧化し、処理前に変更を検出した画像は処理を止める。最大 1,000 画像、画像ごとに 128 MiB、合計 2 GiB、フォルダ内の全項目は最大 20,000 件。画像の処理中に失敗した場合も、すでに保存された結果は残る。中断した場合は保存済みの画像が部分結果として返る。

MCP の `img2img_folder_async` に `prompt` と `image_folder` を渡す。フォルダは出力先か、MCP サーバーの `--allow-dir` / `SDFX_MCP_ALLOWED_DIRS` で許可したローカルフォルダの中に置く。返された `job_id` を `get_job` に渡して進捗と結果を取得できる。単一画像の `init_image` やマスクはこの tool には指定しない。サイズを省略した場合はモデルの既定サイズになる。顔処理は通常どおり `always_on` で `batch_face_swap` を指定する。

開発中の MCP フォルダ処理は Windows のローカルドライブに限る。許可範囲を安全に確認する手段がない OS やネットワークドライブでは明示的に失敗する。各ファイルの検査時とコピー時に Windows の別プロセスを起動するため、画像数が多いフォルダでは準備に時間がかかる。

出力 PNG の生成情報には `NUI img2img source` として元画像の絶対パスが保存される。PNG を他人に渡すときは、そのパスも共有される。GUI ではキュー投入時の画像保護セッションを使う。MCP はデスクトップのパスワードセッションを共有しないため、保護 PNG は扱えない。保護 PNG のフォルダ処理はまだ検証していない。

この機能は開発中。実機の一部と fake engine で確認済みで、全ての Script、保護 PNG、配布版、悪意ある同時パス変更への耐性はまだ検証していない。
