After the txt2img, img2img and Inpaint generation tabs, the main window has tool tabs for checking and processing images and managing models. This page explains what each tab is for and how to use it.

Image inputs work the same way in every tab. Drag and drop a file or a gallery thumbnail, paste from the clipboard with **Ctrl+V**, or click the box to choose a file. **✕** removes the image.

!!! note "Tabs covered on other pages"
    **Embedding Inspector**, **Embedding Editor** and **Embedding Merge** are covered in [LoRA and embeddings](lora-embeddings.html). **ControlNet Fastload** and **ControlNet Fastload Filter** are covered in [ControlNet](controlnet.html).

## PNG Info

Reads the generation parameters embedded in a PNG and sends them back to a generation tab. It works with PNGs generated by A1111, reForge and SDNUI.

![PNG Info tab](shots/png-info.png)

1. Put a PNG in the **Image** box.
2. The **Parameters** box shows the embedded text as is. The table below lists the prompt, negative prompt and each setting as **Field** / **Value**.
3. Choose where to send it:
    - **⇢ txt2img**: restores the parameters in the txt2img tab.
    - **⇢ img2img**: sends the image and parameters to the img2img tab.
    - **⇢ Inpaint**: sends the image and parameters to the Inpaint tab.

For a PNG without parameters, the tab shows the PNG's other text chunks. If there are none, it shows `(no text chunks)`.

## Extras

Upscales images and corrects their colours.

![Extras tab](shots/extras.png)

### Upscaling

1. Put an image in the **Image** box.
2. Choose an upscaler in **Upscaler** and a factor in **Scale** (1 to 8, in steps of 0.25).
3. Press **⤢ Upscale**. The result appears in the **Result** box.

**Upscaler** lists built-in methods such as Lanczos and Nearest, Waifu2x, and ESRGAN-type model files from your model folders. Put model files in `models/upscalers` (`models/ESRGAN`, `models/RealESRGAN`, `models/SwinIR`, `models/ScuNET` and `models/DAT` are also searched). Waifu2x weights are downloaded the first time you use it.

### Colour correction

The **Color correction** box matches the colours of the upscaled result (or the input image, if there is no result yet) to a reference image.

1. Optionally add a reference image. If you leave it empty, the original input is used as the reference.
2. Choose a **Method** (**A1111**, **Wavelet** or **AdaIN**) and a **Strength** (0 to 1).
3. Press **Apply color correction**. With **Also output other methods** on, the other methods' results are saved too, and you can switch between them in the list in the **Result** box.

A1111 matches the histogram and luminosity, AdaIN matches the global colour statistics, and Wavelet matches local colour. Wavelet can produce halos when the reference has a different layout. Output is RGB.

### Using the result

The buttons in the **Result** box pass the result on:

- **Send to Comparison**: compares the input and output in the **Comparison** tab.
- **⇢ img2img** / **⇢ Inpaint**: uses the result as the input image of that tab.
- **⧉** copies the result. **▤** opens its folder.

!!! note "Face restoration"
    The Extras tab itself only upscales and corrects colours. Restore faces, captions, flipped copies and similar steps are applied to generated images by the generation tabs' plugins in the **Extras** group.

## Comparison

Overlays two images and compares them with a movable divider. You can also see how their embedded generation parameters differ.

![Comparison tab](shots/comparison.png)

### Loading images

- To compare two files, put them in **A · first image** and **B · second image**, then press **Compare upload**.
- To compare with a recent result, use these buttons:
    - **Compare img2img** / **Compare Inpaint**: the input image against the img2img or Inpaint result shown.
    - **Compare Extras**: the Extras input against its output.
    - **Compare previous**: the current txt2img result against the previous generation.
- **Selected → A** / **Selected → B** send the image selected in the gallery or preview to A or B.

The original files are not changed. Images of different sizes are fitted without stretching.

### Controls

- Drag over the image to move the divider. Hold **Shift** and drag to pan.
- **Shift** + mouse wheel or **+** / **−** zoom; the arrow keys pan. **Backspace** or **Shift+0** resets the view.
- The **Reveal** (divider position), **B opacity** and **Zoom** sliders and the **Pan** arrow buttons do the same.
- **Horizontal slider (left / right)** changes the divider direction, and **Swap A / B** exchanges the images. **Reset view** resets zoom and position only and keeps the divider and opacity.
- **Export PNG…** saves the visible comparison as a new PNG.

Open **Infotext · changed tags and fields are marked in red** to see the prompts and settings of A and B side by side, with differing tags and fields in red.

### Comparison options

**Comparison options** sets how the send buttons appear in other tabs (**Off**, **Text** or **Icon**) and mouse shortcuts. With **Ctrl+Alt+left/right click an image to send to A/B** on, Ctrl+Alt+left-click sends an image to A and Ctrl+Alt+right-click sends it to B. With **Switch to Comparison after image shortcut** on, the app then switches to the Comparison tab.

## Styles

Edits prompt styles (`styles.csv`) in a table. Extended presets, which also include the model and image size, are edited on the same screen.

![Styles tab](shots/styles.png)

### Choosing what to edit

- In the first list, choose **Prompt styles** or **Extended presets**.
- For prompt styles, the category list offers **Master styles** and each category.
- The search box searches every column. Choose the match type: **Exact match**, **Case insensitive** or **regex**.
- For extended presets, **Current model + VAE** shows only presets that match the current model and VAE.

### Editing styles

- Double-click a cell to edit it. Edits save automatically after a short pause or when you leave the field.
- **Selected style** on the right shows every field of the selected style. Press **Save / merge changes** to save edits made there.
- Toolbar buttons:
    - **New**: creates an empty style.
    - **From prompts…**: creates a style from the current prompt and negative prompt.
    - **Duplicate** / **Delete**: duplicates or deletes the selected styles.
    - **↑** / **↓**: change the order. With **Autosort** on, styles are sorted automatically.
    - **Move to…**: moves the selected styles to another category. **New category…** creates a category.
    - **Apply**: applies the selected style to the generation tab.
    - **Reload**: reads the file again.
- **Replace all** replaces literal text across the whole file, including hidden rows.

On the keyboard, **D** duplicates, **Delete** removes and **M** moves to a category. **Ctrl/Cmd+X/C/V** cut, copy and paste a single cell. Duplicate prompt-style names gain an `x`.

Extended presets are stored separately from prompt styles. Applying one restores only the prompts, size, model and VAE.

### Backups

Open **Backups · prompt styles and categories** to work with backups. Changed prompt styles are backed up every ten minutes, and the latest 24 backups are kept.

- **Back up now**: makes a backup immediately.
- **Restore**: restores `styles.csv` and its categories from the selected backup (CSV or `.aes`). The current file is backed up first.
- **Export…**: exports the selected backup, or the current file.
- Turn on **Encrypt future backups (.aes)** and enter a password to encrypt later backups. The password is never saved. The active CSV files stay unencrypted.

## Tokenizer

Shows how the loaded model's CLIP tokenizer splits text into tokens. No image is generated.

![Tokenizer tab](shots/tokenizer.png)

1. Load a checkpoint.
2. Choose the input mode, **Text** or **Token IDs**. For **Token IDs**, enter comma-separated integers.
3. Type the text, or press **Use current prompt** to copy the positive prompt from the active generation tab.
4. Press **Inspect tokens**.

The result shows the token count, the BOS, EOS and PAD IDs, the list of token IDs, the text decoded by the tokenizer, and a table of tokens (**ID**, **BPE piece**, **Display**, **UTF-8 bytes**, **Special**). Click a coloured group to copy its IDs, or press **Copy all IDs**. For SDXL, the two tokenizers are shown separately.

!!! note "Difference from tokenization during generation"
    This tab tokenizes literally. It adds no BOS or EOS and does not expand attention syntax, schedules, `BREAK`, LoRA tags or embeddings. During generation, the prompt may be split into chunks or transformed.

## VAE Tools

Encodes images into latents with the VAE and decodes latents back into images. Use it to see VAE compression, edit latents or decode with a different VAE. It uses the checkpoint and VAE selected in the top bar, so load a checkpoint first.

![VAE Tools tab](shots/vae-tools.png)

1. Choose an **Operation**: **encode**, **decode** or **encode+decode**.
2. Choose a **Representation** for saved latents: **L**, **RGBA** or **CMYK**.
3. Choose an **Approximation** for decoding: **Full**, **Approx NN**, **Approx cheap** or **TAESD**.
4. Press **Choose files…**, or type paths into the input box, one per line.
5. Choose where to save with **Output folder…**, then press **Run VAE Tools**.

The representations differ as follows:

- **L**: a grayscale PNG that holds the exact latent tensor.
- **RGBA** / **CMYK**: the four latent channels are quantized to 8 bits over [-10, 10]; values outside the range are clipped. Sixteen channels use a 2×2 grid.
- For CMYK, **CMYK save format** offers **TIFF** or **JPEG100**. TIFF keeps all channels; JPEG100 still adds loss.

Decode accepts unchanged L or RGBA PNGs, CMYK TIFF or JPEG files, and `tensor.safetensors`. Do not resize L or RGBA PNGs, flatten their alpha or convert them to lossy formats.

Decoding methods:

- **Full**: uses the selected VAE.
- **TAESD**: uses madebyollin/taesd or taesdxl. The first use needs cached weights or **Allow optional model downloads**.
- **Approx NN**: uses the official A1111 weights and decodes at twice the latent size. Give the weights file path, or allow downloads.
- **Approx cheap**: decodes at the latent size.

Only **Full** and **TAESD** can encode; other choices encode with Full. **Tiled VAE** uses diffusers VAE tiling for this operation only and restores the previous setting afterwards.

While it runs, **Interrupt** requests cancellation. Results and saved paths appear under **Result metadata and saved paths**. Input files are not changed.

!!! warning "Image scrambling"
    Even with image scrambling on, L and CMYK latent files, safetensors and reports are saved readable. To encode, you must turn on **Allow readable plaintext latent files for this run**.

## Metadata Utils

Shows the metadata in a checkpoint or LoRA safetensors file and saves an edited copy. Model weights are not loaded.

![Metadata Utils tab](shots/metadata-utils.png)

1. Choose **Checkpoint** or **LoRA**, then choose a file. If the list is out of date, press **Refresh**.
2. Press **Load metadata**. The metadata appears as JSON.
3. Edit the JSON.
4. Optionally enter a new filename stem. If you leave it empty, `_md` is appended to the original name.
5. Press **Save copy**. A new file is saved in the same folder as the original.

- Existing files are never overwritten; saving to a name that already exists is rejected.
- Tensor bytes stay the same, but changing metadata changes the file hash.
- JSON values are stored as strings; objects and other values are stored as JSON text. Saving an empty object `{}` clears the copy's metadata.
- **Cancel** cancels only this metadata operation.

## Model Presets

Saves generation-setting presets per checkpoint and sends them to the generation tabs (the heading on screen is **Model Preset Manager**). It also keeps the model page URL, trigger words and a thumbnail.

![Model Presets tab](shots/model-presets.png)

### Choosing a model

Choose a checkpoint and press **Retrieve model info**, or press **Use loaded model** for the model currently loaded. Presets are keyed by the checkpoint's SHA256, so the first time takes a while to compute the hash.

!!! note "Communication with Civitai"
    When no URL is saved, **Retrieve model info** and **Use loaded model** ask Civitai for information by sending the checkpoint's full SHA256 hash (64 characters). The model file itself is never sent. Automatic retrieval only updates the URL, trigger words and a missing thumbnail. To import sharing presets from Civitai, press **Download and overwrite info**.

### Creating and using presets

1. Enter a preset name and write the generation parameters (infotext) in **Generation data**. **Use generated image parameters** fills in the parameters of the generated or selected image. **Append template** adds a template.
2. Press **Save preset**. **Save as default** makes it the default preset, and **Rename preset** / **Delete preset** rename or delete it.
3. Press **Send to txt2img**, **Send to img2img** or **Send to Inpaint** to send the settings to a generation tab.

Unsaved edits are kept per preset. A name change takes effect when you press **Save preset** or **Rename preset**.

### Model information and sharing

- Enter the model page URL in **Model page URL** and press **Save URL / trigger words**. **Open model page** opens it in your browser.
- Write one trigger word per line in **Trigger words**.
- **Replace thumbnail…** replaces the thumbnail; a 300px PNG is saved beside the checkpoint. **Reveal presets folder** opens the folder where presets are saved.
- **Import JSON / sharing text** reads a preset JSON file or sharing text, and **Export JSON** writes presets to a JSON file. Export never overwrites an existing file.
- **Get sharing text** creates text for sharing, and **Copy sharing text** copies it.

## Model Keywords

Checks and registers the keywords (trigger words) for checkpoints and LoRAs. The **Model Keyword** plugin in the generation tabs uses these mappings when it inserts keywords into the prompt.

![Model Keywords tab](shots/model-keywords.png)

1. Choose **Checkpoint** or **LoRA**. For a LoRA, pick it from the list. For a checkpoint, the checkpoint selected in the top bar is used.
2. Press **Check** to see the registered keywords. The result shows the filename, hash and where the mapping came from.
3. To register your own keywords, enter them separated by `|` and press **Save**. **Delete** removes your own mapping.

The upstream mapping tables (mix1009/model-keyword) are included, so lookups work offline. Your own mappings are saved in the `model-keyword` folder in the configuration folder. **Download upstream LoRA catalog…** downloads the pinned LoRA catalog (about 31 MB) from GitHub into the configuration folder. It does not replace an existing catalog.

In the generation tabs, the **Model Keyword** plugin sets where keywords go (**Keyword placement**), which checkpoint keywords to use (**Checkpoint keywords**), a LoRA and its weight (**LoRA model**, **LoRA multiplier**), the LoRA keywords (**LoRA keywords**) and an embedding (**Textual inversion embedding**).

## Image Scrambling

Rearranges image pixels with a password when saving. It reads and writes a format compatible with the upstream sd-encrypt-image extension. The tab has two pages, **Session** and **Batch conversion**.

![Image Scrambling tab](shots/image-scrambling.png)

!!! warning "This is not secure encryption"
    This is pixel scrambling, not secure encryption. Metadata stays readable and can include thumbnails of the original image. Do not rely on it to protect images that must stay private.

### Session

Scrambles the images generated in this session.

1. Enter a password and press **Enable for this session**. The password is not saved.
2. Images from jobs started after this are saved scrambled. Inside the app, they are displayed normally using the password.
3. To stop, press **Turn off**. Later jobs save ordinary images.

- Jobs already in the queue keep the setting they were queued with.
- Videos and their temporary frames are not scrambled. To export videos, turn on **Allow plaintext video exports for this session**. This choice resets when the session is turned off.
- After a crash, temporary input files can remain readable. VAE recovery tensors also remain readable. Custom Code can save readable files.
- The MCP server runs separately from this session, so the session setting does not apply to MCP.

### Batch conversion

Scrambles or restores all images in a folder.

1. Choose the **Source folder** and **Output folder** with **Browse…**.
2. Enter the password and choose **Scramble images** or **Restore images**.
3. Press **Start**. To stop partway, press **Stop after current image**.

- Source files are not changed. Files that already exist in the output folder are skipped.
- Output is PNG. Restoring brings back the pixels only, not the original JPEG or WebP bytes. Some JPEG or WebP metadata may be lost.
- To restore older images that carry no information for checking the password, turn on **Restore legacy images even when the password cannot be verified**.

## Temporal Lab

Processes image sequences and frame folders. It offers DFI, which stabilizes a generated sequence against reference frames, plus Deflicker, Fuse and frame extraction from video. The screen and processing follow the Abysz LAB extension, but exact numerical parity with the original is not claimed.

![Temporal Lab tab](shots/temporal-lab.png)

Input folders are only read and never changed. Each run creates a new folder named in **New folder** under **Output parent** in the **Output** box. Existing files are never overwritten.

### DFI

Choose the **Reference frames** and **Generated frames** folders, then adjust **Source denoise**, **Tolerance**, **Expand**, **Mask smoothing**, **Inter denoise**, **Inter size**, **Inter frequency**, **Inter blur**, **Refresh frequency** and **Preserve %**. Set **Frame limit** to 0 to process all frames.

- **Preview mask**: shows the mask for the frame set in **Preview transition** in **Mask preview**.
- **Run DFI**: runs the processing.

### Deflicker

Choose the **Frames** folder, set **Temporal blend**, **Overlay** and **Normalize brightness**, then press **Run deflicker**.

### Fuse

Choose the **Style frames** and **Video frames** folders, set **Strength**, then press **Fuse frames**. Style frames are resized to the video frame size.

### Extract

Choose a **Video file**, set **FPS**, then press **Extract frames**. An FPS of 0 uses the source video's FPS.

### Checking the result

**Output preview** shows the output frames. **Play**, **Pause** and **Stop** control playback, and you can change the FPS. **Cancel** requests cancellation of a running job.

## VRAM Estimator

Runs real generations with the loaded CUDA model and measures VRAM use for each image size and batch size. The results feed the VRAM estimate shown at the top of the generation tabs.

![VRAM Estimator tab](shots/vram-estimator.png)

1. Load a checkpoint.
2. Set **Maximum side** (256 to 2048), **Maximum batch** (1 to 16) and **Steps**.
3. Press **Run calibration**. It runs four workloads (txt2img, Lanczos hires, latent hires and img2img) over the sizes and batch sizes.
4. The results appear as one chart per workload, with pixels on the horizontal axis and additional reserved VRAM on the vertical axis.

- **Stop calibration** stops the run. Completed measurements stay in the history.
- When a size fails, for example by running out of memory, larger sizes for the same workload and batch size are skipped.
- **Reload history** reads saved measurements again. **Export profile…** and **Import profile…** write and read measurements.

When a matching calibration exists, the generation tabs show a "Vanilla VRAM estimate". Values outside the measured range are marked "extrapolated".

!!! note "What the estimate covers"
    Only plain workloads are measured; extension costs are excluded. A finite sweep does not guarantee what your device can handle.

## System Info

Shows the engine's runtime, libraries, model inventory and GPU status, and runs benchmarks. Nothing is sent anywhere automatically.

![System Info tab](shots/system-info.png)

Buttons at the top:

- **Refresh data**: refreshes the runtime, libraries and model inventory. While the tab is visible, it refreshes every 5 seconds.
- **Hash inventory**: reads model files to calculate SHA256 prefixes. This can take time.
- **Export JSON…**: saves the report shown in **Info JSON**.
- **Send interrupt**: interrupts the engine's active request, including a benchmark.

Pages below:

- **Overview**: a table of fields and values, and a chart of GPU utilization and GPU memory.
- **Models & Networks**: the model and network inventory.
- **Benchmark**: a fixed-scene benchmark. Choose **Level** (quick, normal, extensive or ludicrous), **Steps** (turbo, default or long), **Width** and **Height**, then press **Run benchmark**. **Warm up first (excluded from scores)** runs a warm-up first. Results are saved to a local history and can be exported with **Export benchmark JSON…**.
- **Info JSON**: the whole report as JSON.

**Optional legacy cloud submission** can send a benchmark result to the original extension's public results service. **Preview submission** shows exactly what will be sent, and nothing is sent until you press **Submit previewed payload**. Receipt cannot be confirmed.

### Writing to image metadata

- **Hardware image metadata (opt-in)**: with **Write hardware and time into future images** on, later generated PNGs and Extras PNGs include hardware information, the time taken and an optional **Remark**.
- **Image metadata (opt-in)**: writes the selected system-information fields into later generated PNGs. All fields start off.
